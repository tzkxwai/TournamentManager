
# Архитектура TournamentManager

## О проекте

TournamentManager — приложение для проведения турниров
и ведения рейтинга игроков.

Администратор сможет создавать турниры, добавлять
участников, составлять турнирную сетку и записывать
результаты матчей.

Обычные пользователи смогут просматривать турниры,
результаты матчей и рейтинг игроков.

## Структура программы

Программа будет состоять из трёх отдельных сервисов
и веб-интерфейса.

### PlayerService

Отвечает за пользователей и игроков.

Основные функции:
- регистрация и вход в систему;
- авторизация с помощью JWT;
- управление игроками;
- хранение рейтинга игроков.

### TournamentService

Отвечает за проведение турниров.

Основные функции:
- создание турниров;
- добавление участников;
- формирование олимпийской турнирной сетки;
- определение победителя турнира.

### MatchService

Отвечает за матчи и результаты.

Основные функции:
- хранение информации о матчах;
- запись результатов;
- определение победителя матча;
- расчёт нового рейтинга по системе Эло.

## Базы данных

У каждого сервиса будет отдельная база данных SQLite.

PlayerService:
- Users — пользователи;
- Players — игроки и их рейтинги.

TournamentService:
- Tournaments — турниры;
- TournamentPlayers — участники турниров.

MatchService:
- Matches — матчи;
- RatingHistory — история изменения рейтинга.

Сервисы не будут обращаться напрямую к чужим
базам данных.

## Взаимодействие сервисов

Веб-интерфейс будет отправлять запросы к сервисам
через HTTP API.

Сервисы смогут обмениваться информацией через HTTP.
Для асинхронного обмена событиями будет использоваться
очередь сообщений.

Например, после завершения матча MatchService
сможет отправить событие с результатом, чтобы
другие сервисы обновили нужные данные.

## Расчёт рейтинга

Для расчёта рейтинга будет использоваться система Эло.

После каждого завершённого матча рейтинг победителя
и проигравшего будет пересчитываться с учётом
их предыдущих рейтингов.

Расчёт будет вынесен в отдельную часть программы,
чтобы его можно было проверить автоматическими тестами.

## Безопасность

Для входа будет использоваться JWT.

В программе будут две роли:

Admin — создание турниров, управление игроками
и внесение результатов матчей.

User — просмотр турниров, матчей и рейтинга.

## Запуск программы

Сервисы будут запускаться с помощью Docker Compose.

Для проверки API будет использоваться Swagger.

Для поиска ошибок будет добавлено логирование
и проверка работоспособности сервисов.

## Принятые решения

ASP.NET Core выбран для создания веб-сервисов,
поскольку он подходит для разработки на C#.

SQLite выбрана из-за простоты настройки.
Для учебного проекта отдельного сервера базы данных
не требуется.

Веб-интерфейс будет сделан на ASP.NET Core MVC.

Для тестирования будет использоваться xUnit.

## Ограничения

В первой версии будет поддерживаться только
олимпийская система турниров.

В дальнейшем можно добавить круговые турниры,
командные соревнования и другие способы
расчёта рейтинга.
